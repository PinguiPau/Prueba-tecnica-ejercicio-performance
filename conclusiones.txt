     obteniendo una tasa de error del 0.00% en todo el ciclo de prueba.


3. ANÁLISIS DE ARQUITECTURA Y COMPORTAMIENTO TÉCNICO
   - Eficiencia en la Carga de Datos (SharedArray): La lectura parametrizada 
     del archivo 'usuario.csv' mediante SharedArray demostró ser óptima, 
     garantizando que la memoria RAM del ejecutor de K6 se mantuviera baja y 
     sin sobrecostos de I/O por cada VU activa.

   - Respuesta del Endpoint (/auth/login): FakeStoreAPI respondió a cada 
     solicitud con código de estado HTTP 201 Created (o 200 OK según endpoint), 
     retornando en todas las iteraciones la estructura JSON esperada con el 
     token de autenticación JWT.


4. CONCLUSIÓN GENERAL Y RECOMENDACIÓN DE QA
   - Conclusión: La API de autenticación evaluada cumple plenamente con los

     una carga constante de 20 TPS.
